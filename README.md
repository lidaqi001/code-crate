# 码匣 CodeCrate

面向开发者的高频工具集浏览器扩展（Manifest V3）。**零权限、纯本地、无需构建**，改完代码刷新扩展即可生效。

## 为什么值得用

| 维度 | 做法 |
| --- | --- |
| 隐私 | `permissions` 为空数组；除 HTTP 外的 28 个工具完全离线，HTTP 工具只在你主动发送时按主机名申请权限（覆盖该主机所有端口） |
| 安全 | 全项目禁用 `innerHTML` / `insertAdjacentHTML` / `srcdoc` / `document.write` / `eval` / `new Function`，界面只用 DOM 与 `textContent` 构建 |
| 可靠 | 核心逻辑与界面分离，单元测试覆盖哈希向量、时区夏令时、随机数无偏性、LCS diff、二维码容量表等易错点 |
| 无障碍 | 表单标签自动与控件关联（点标签即可聚焦）、`aria-label`、键盘可达、可见焦点环、尊重「减少动效」、`color-scheme` 与 `lang` |
| 无死链 | 工具注册表与目录双向一致由自检脚本强制校验 |
| 体验 | 统一的深浅色设计系统、全部工具首页、命令面板、模糊搜索、键盘操作、最近使用、输入自动记忆（密钥类默认不落盘）、失败必提示 |
| 可维护 | 原生 ESM，无打包步骤，无第三方运行时依赖 |

## 安装

1. 打开 `edge://extensions/`（Chrome 为 `chrome://extensions/`）
2. 打开右上角「开发人员模式」
3. 点击「加载解压缩的扩展」，选择本仓库根目录（包含 `manifest.json` 的那一层）
4. 固定到工具栏后点击图标即可使用

每次修改代码后，在扩展管理页点击「重新加载」即可，**不需要任何构建命令**。

> Wi-Fi 二维码、SVG 占位图与图片工具都在本地生成/处理，图片与网络密码不会离开设备。
> 图片工具直接读文件头拿尺寸与 EXIF（不解码整张图），EXIF 解析同时支持小端与大端字节序。

> 加密与动态口令全部用浏览器原生 WebCrypto 在**本地**计算，密钥与口令不出设备；
> 「加密与摘要」的实现已用 `node:crypto` 做双向交叉验证，动态口令对齐 RFC 4226 / 6238 官方向量。

> 二维码编码器与格式转换器（YAML / TOML / XML / CSV 解析器）都不依赖任何第三方库。
> 它们都**明确限定支持范围**并在越界时报错，而不是猜：
> 二维码只收录能用公开容量表逐项验证的版本 1–8；YAML 不支持锚点、别名、标签与多文档；
> TOML 的日期时间按字符串处理，且 null 无法表示（会报错并指出位置）。

## 使用技巧

- `Ctrl/Cmd + K`：打开命令面板，可跳转任意工具或执行当前工具的动作
- `Ctrl/Cmd + Enter`：执行当前工具的主操作（如「格式化 JSON」「生成一批」）
- popup 中 `↑` `↓` 选择、`Enter` 打开、`/` 聚焦搜索；`☆` 可置顶常用工具
- 除密钥与文件内容外，工具的输入会自动保存，下次打开时恢复

## 开发

### 目录结构

```
code-crate/
├── manifest.json           # MV3 清单，零权限
├── src/
│   ├── core/               # 设计令牌、基础组件、主题、命令面板、模糊搜索、工具页外壳
│   ├── home/               # 全部工具首页（大网格、搜索、置顶/最近分组）
│   ├── popup/              # 工具栏弹窗
│   └── tools/<工具 id>/
│       ├── index.html      # 页面骨架（只放静态结构）
│       ├── logic.js        # 纯逻辑，无 DOM —— 单元测试只测这一层
│       ├── ui.js           # 界面与事件绑定
│       └── style.css       # 工具专属样式
├── test/                   # node:test 单元测试
└── scripts/                # check.mjs 静态自检 · smoke.mjs 浏览器冒烟 · package.mjs 打包
```

### 新增一个工具

1. 建目录 `src/tools/<id>/`，包含 `index.html`、`logic.js`、`ui.js`（可按需加 `style.css`）
2. 页面里写 `<body data-tool="<id>">`，引入 `../../core/tokens.css`、`base.css`，并在 `<head>` 首行引入 `../../core/theme-init.js`
3. `ui.js` 中调用 `mountTool({ actions: [...] })` 注册动作
4. 在 `src/core/registry.js` 的 `TOOLS` 中登记一行
5. 在 `test/<id>.test.js` 补充纯逻辑单测
6. 运行 `npm run verify` 确认无死链、无禁用 API、测试与冒烟全部通过

### 质量门

```bash
npm test     # 单元测试（纯逻辑层）
npm run lint # 静态自检：清单、注册表一致性、资源引用、禁用 API、ESM 导入路径、无障碍
npm run smoke # 浏览器验证：Chrome 校验清单 + 无头浏览器逐个打开全部工具视图
npm run verify # 以上三项全跑
npm run package # 打包上架 zip（先自检，产物在 dist/）
```

自检脚本会强制以下约束，不通过则退出码非零：

- 注册表登记的每个工具都真实存在，且 `src/tools` 下没有未登记的目录（杜绝死链）
- manifest 引用的图标与页面都存在；CSP 不含 `unsafe-eval`
- 所有 HTML 的本地 `href`/`src` 都能解析
- 源码中不出现 `innerHTML` / `outerHTML` / `insertAdjacentHTML` / `srcdoc` / `document.write` / `eval` / `new Function` / `javascript:` URL / `on*` 事件属性
- ESM 导入路径可解析（语法检查发现不了写错的 import）
- `ui.js` 里用到的 `els.X` 必须先赋值（这类遗漏只在运行时抛 TypeError）
- 每个工具页都有 `lang`、`color-scheme`、主题预置脚本、`data-tool` 与设计系统样式
- `role="tab"` 必须配套 `role="tablist"`

浏览器验证分为三部分：

1. **清单校验**：把扩展交给 Chrome 自己打包，用真实的清单解析器把关
2. **界面冒烟**：用本地静态服务器托管扩展目录，无头浏览器逐个打开 popup、全部工具首页与全部工具页，
   并**依次点开每个标签页**，检查每个视图都能渲染、`label` 均已关联、控制台无报错
3. **交互探针**：对部分工具再往下走一步，真的驱动一次核心操作并核对产物
   （例如给格式转换喂一段 JSON，断言输出里出现了预期的 YAML），
   避免「渲染正常但点了没反应」这类问题漏过

> 边界说明：Chrome / Edge 152 起已移除命令行加载未打包扩展的能力（`--load-extension` 失效），
> 所以冒烟测试把页面当普通网页运行。它覆盖全部界面与纯逻辑，但**不覆盖**
> `chrome.tabs` / `chrome.permissions` / offscreen 等扩展专有 API —— 那部分需手动
> 「加载解压缩的扩展」验证。脚本在未安装浏览器时会自动跳过。

## 隐私

- 扩展**不申请任何必需权限**，不注入页面，不读取浏览记录
- 除 HTTP 工具外，其余 28 个工具**不发起任何网络请求**，全部在本地完成计算
- 偏好设置与多数工具的输入只写入浏览器本地存储 `localStorage`，不联网、不上传；加密、动态口令等工具的密钥/明文默认**不落盘**，需显式勾选「在本机记住」
- **HTTP 工具是唯一的例外，并且完全由你控制**：
  - `manifest.json` 只声明 `optional_host_permissions`，安装时**不授予任何主机权限**
  - 只有当你点击「发送」时，才会针对该请求的主机名弹出授权提示（覆盖该主机所有端口）；拒绝则请求不会发出
  - 已授权的主机会显示在工具页底部，可随时点「撤销」回收
  - 请求由 `fetch` 直接发出，不经过任何中间服务器

Markdown 预览若包含远程图片，浏览器会去加载这些图片——这是图片本身的地址决定的，
与本扩展无关；不需要该行为时请在原文中移除图片标记。
